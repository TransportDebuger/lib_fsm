# s21 FSM Library (ver. 1.0)

## Обзор

s21 FSM Library — это универсальная C‑библиотека для реализации конечных автоматов (Finite State Machines, FSM), предназначенная для использования как в чистых C/C++‑проектах, так и из других языков через FFI (Python, Go, Java и др.).

Библиотека предоставляет:

- модель состояний и переходов, совместимую с UML‑семантикой (entry / do / exit, guard / effect).
- динамическую регистрацию состояний и переходов во время выполнения.
- глобальный контекст FSM и контексты для каждого состояния и перехода.
- защиту от реэнтрантных вызовов `dispatch` и `update`.
- стабильный и минималистичный C‑API, рассчитанный на долгосрочное повторное использование.

Эта библиотека используется как «ядро» во всех проектах BrickGame (Tetris, Snake) и может быть переиспользована в любых других задачах, где требуется формализация логики через конечные автоматы.

## Ключевые концепции

### Состояния

Состояние идентифицируется целым числом (`s21_state_id_t`), которое должно быть неотрицательным (≥ 0).

Для каждого состояния можно зарегистрировать:

- три callback‑функции:
  - `on_entry(ctx)` — вызывается при входе в состояние;
  - `on_do(ctx)` — вызывается при обновлении состояния (`s21_fsm_update`);
  - `on_exit(ctx)` — вызывается при выходе из состояния при успешном переходе.
- контекст состояния (`state_ctx`), который будет передаваться во все его callbacks.

Состояние может иметь произвольное количество исходящих переходов.

### Переходы

Переход задаётся:

- исходным состоянием (`src_state_id`),
- целевым состоянием (`dest_state_id`),
- идентификатором события (`trigger`),
- опциональными callback‑функциями:
  - `on_guard(ctx)` — guard‑условие; если `NULL`, переход всегда разрешён;
  - `on_effect(ctx)` — effect‑действие, вызываемое при выполнении перехода.

Каждый переход имеет собственный контекст (`transition_ctx`), который передаётся в его callbacks.

### События

Событие представляет собой целочисленный идентификатор (`s21_event_id_t`, ≥ 0), который передаётся в `s21_fsm_dispatch`.

При вызове `dispatch`:

- библиотека ищет среди переходов текущего состояния первый переход с совпадающим `trigger`,
- проверяет guard‑условие (если оно задано),
- при успехе выполняет переход (exit → effect → смена состояния → entry).

Если подходящего перехода нет, возвращается `S21_FSM_NO_TRANSITION` и состояние не меняется.

### Контексты

Библиотека оперирует тремя уровнями контекста:

- глобальный контекст FSM (`user_ctx`) — задаётся при создании и через `s21_fsm_set_context`.
- контекст состояния (`state_ctx`) — задаётся при регистрации/обновлении состояния и может быть изменён через `s21_fsm_set_state_context`.
- контекст перехода (`transition_ctx`) — задаётся при регистрации перехода и может быть изменён через `s21_fsm_set_transition_context_exact`.

Особенности:

- все контексты могут быть `NULL`;
- библиотека не интерпретирует и не освобождает память по этим указателям;
- тип и структура контекста полностью определяются пользователем.

## Жизненный цикл FSM

### Создание и уничтожение

1. Создание:

   ```c
   s21_fsm_t *fsm = s21_fsm_create(user_ctx);
   ```

   - при ошибке аллокации возвращается `NULL`.

2. Уничтожение:

   ```c
   s21_fsm_destroy(fsm);
   ```

   - безопасно вызывать с `NULL`;
   - освобождаются все состояния, их переходы и сама FSM.

### Настройка модели

Типичный порядок:

1. Регистрация состояний:

   ```c
   s21_fsm_register_state(fsm, STATE_IDLE,  on_entry_idle, on_do_idle,  on_exit_idle,  idle_ctx);
   s21_fsm_register_state(fsm, STATE_RUN,   on_entry_run,  on_do_run,   on_exit_run,   run_ctx);
   s21_fsm_register_state(fsm, STATE_ERROR, on_entry_err,  NULL,        NULL,          err_ctx);
   ```

2. Регистрация переходов:

   ```c
   s21_fsm_register_transition(fsm, STATE_IDLE, STATE_RUN,   EVENT_START,   NULL,          on_effect_start,   start_ctx);
   s21_fsm_register_transition(fsm, STATE_RUN,  STATE_IDLE,  EVENT_STOP,    NULL,          on_effect_stop,    stop_ctx);
   s21_fsm_register_transition(fsm, STATE_RUN,  STATE_ERROR, EVENT_FAIL,    on_guard_fail, on_effect_fail,    fail_ctx);
   ```

3. Установка начального состояния:

   ```c
   s21_fsm_set_initial_state(fsm, STATE_IDLE);
   ```

### Инициализация и сброс

Перед обработкой событий FSM должна быть инициализирована:

```c
int rc = s21_fsm_initialize(fsm);
```

- устанавливается `current_state = initial_state`,
- вызывается `on_entry` начального состояния (если задан),
- флаг `initialized` становится `true`.

Для повторного запуска FSM можно использовать:

```c
s21_fsm_reset(fsm);
```

- аналогично `initialize`, но также сбрасывает внутренние флаги `in_dispatch` и `in_update`; предполагается, что FSM уже была настроена.

### Обработка событий и обновление

Обработка событий:

```c
int rc = s21_fsm_dispatch(fsm, event);
```

- при `event < 0` возвращается `S21_FSM_EVENT_INCORRECT_ID`,
- при неинициализированной FSM — `S21_FSM_NOT_INITIALIZED`,
- при `fsm == NULL` возвращается `S21_FSM_NULL_POINTER`,
- при отсутствии текущего состояния — `S21_FSM_STATE_NOT_FOUND`,
- при отсутствии перехода — `S21_FSM_NO_TRANSITION`.

Обновление состояния (вызов `on_do`):

```c
s21_fsm_update(fsm);
```

- при наличии `on_do` у текущего состояния вызывается callback с контекстом состояния;
- если `on_do == NULL`, возвращается `S21_FSM_OK` без дополнительных действий;
- при `fsm == NULL` возвращается `S21_FSM_NULL_POINTER`, при отсутствии текущего состояния — `S21_FSM_STATE_NOT_FOUND`.

Защита от реэнтрантности:

- при вложенном вызове `dispatch` или `update` возвращается `S21_FSM_REENTRANT_CALL`.

## Использование из разных языков

Публичный API библиотеки ориентирован на использование через C‑FFI:

- интерфейс использует только примитивные типы (`int32_t`, `bool`) и `void *`;
- структура `s21_fsm_t` непрозрачна (opaque);
- сигнатуры функций стабильны и не зависят от конкретной реализации.

Это позволяет:

- напрямую использовать библиотеку в C и C++ проектах;
- оборачивать её в Python (ctypes/cffi), Go (cgo), Java (JNI/JNA) и других языках.

## Группы API

Публичные функции разбиты на следующие группы:

- **Lifecycle** — создание, уничтожение, инициализация, сброс, глобальный контекст.
- **States** — регистрация, обновление, удаление, начальное/текущее состояние, контекст состояния.
- **Transitions** — регистрация, удаление, очистка по триггерам, контекст перехода.
- **Events** — обработка событий (dispatch) и обновление состояния (update).

Подробное описание функций и их аргументов см. в `include/s21_fsm.h`, реализации `src/s21_fsm.c` и соответствующих разделах Doxygen в `docs/`.

## Ограничения и оговорки

- Идентификаторы состояний и событий должны быть неотрицательными (≥ 0). Отрицательные значения считаются ошибкой.
- Библиотека не является многопоточной; параллельный доступ к одной FSM должен синхронизироваться внешним кодом.
- Пользователь несёт ответственность за корректное управление памятью по указателям контекста; FSM только хранит и передаёт эти указатели.
- API версии 1.0 считается замороженным; новые возможности добавляются через расширение (добавление функций), а не изменение существующих сигнатур.
